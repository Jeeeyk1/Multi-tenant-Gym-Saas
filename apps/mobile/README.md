# @gym-saas/mobile

Expo 54 mobile application for the FitOps platform.

## Local development

```bash
# From the repo root:
pnpm dev:mobile

# Or from this directory:
pnpm start
```

Scan the QR code with the Expo Go app, or press `i` for iOS simulator / `a` for Android emulator.

## Environment

Copy `.env.example` to `.env` and adjust as needed.
Expo reads variables prefixed with `EXPO_PUBLIC_` at build time.

| Variable               | Description                      |
|------------------------|----------------------------------|
| `EXPO_PUBLIC_API_URL`  | Base URL for the API             |
| `EXPO_PUBLIC_LANDING_URL` | Landing site, for the Terms and Privacy links |

## Monorepo config

`metro.config.js` extends Expo's default Metro config to watch the workspace root,
enabling Metro to resolve `workspace:*` packages like `@gym-saas/contracts`.

## UI kit and motion

Shared building blocks live in `src/components/ui` (import from `components/ui`):

| Component | Use it for |
|---|---|
| `Button` | Every button. `status` goes idle → loading → success; primary uses the gym's colour. |
| `PressableScale` | Any custom tappable card or row that should shrink slightly when pressed. |
| `Sheet` | Bottom sheets (drag down, backdrop tap or back to close). Use `BottomSheetTextInput` inside. |
| `useToast()` | Results and errors (`show('Saved')`, `{ tone: 'error' }`, `{ action: { label: 'Undo', … } }`). Keep `Alert.alert` for questions that need an answer. |
| `Skeleton` | Loading placeholders shaped like the content, instead of a centred spinner. |
| `EmptyState` | Empty lists, and failed loads with a "Try again" action (`tone="error"`). |
| `ScreenHeader` | Member screen headers with a 44pt back button and safe-area padding. Staff screens keep `StaffHeader`. |

Animations use Reanimated with the three springs in `src/theme/motion.ts` (`snappy`, `gentle`, `bouncy`). They
follow the OS "Reduce Motion" setting automatically. Haptics go through `src/lib/haptics.ts`
(`tap`, `press`, `success`, `error`) so the same moment always feels the same.

Reanimated, Gesture Handler and `@gorhom/bottom-sheet` are native modules: after pulling a change that adds or
upgrades one, run `pod install` in `ios/` and rebuild the app (`pnpm ios` alone is not enough).

## Native iOS project

`ios/` is generated by `expo prebuild`. Xcode 27 / iOS 27 fixes live in
`plugins/with-ios27-fixes.js` and are re-applied on every prebuild:

- raises pods below iOS 15.1 to the app's deployment target (Podfile `post_install`)
- adopts the UIScene lifecycle (`SceneDelegate` in `AppDelegate.swift` + `UIApplicationSceneManifest`)

Don't hand-edit these in `ios/`; change the plugin instead.

## Production builds

Use [EAS Build](https://docs.expo.dev/build/introduction/) for production:

```bash
npm install -g eas-cli
eas build --platform all
```
