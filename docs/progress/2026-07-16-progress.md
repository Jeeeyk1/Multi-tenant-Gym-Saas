## AI Insights bug fixes (found during e2e testing)

Two bugs in the admin AI assistant, surfaced by asking "how many active members" and getting
`**0**` when the dashboard showed 4.

1. **Active-members count returned 0 (correctness).** The model passes the status filter as
   natural-language `"active"`, but `gym_members.status` is stored upper-case (`ACTIVE`, per
   `gym_members_status_check`), and Postgres string matching is case-sensitive → 0 rows. Root
   cause: the `query_metric` whitelist mapped the `status` *column* but never constrained its
   *values*, and the tool schema/system prompt never told the model the valid set.
   **Fix:** added `filterValues` to the metric whitelist (members `status`, checkins `method`);
   `validateMetricQuery` now normalizes enum-like filter values case-insensitively to the stored
   value and rejects anything outside the set (also a small security tightening). The allowed
   values are now surfaced in the system prompt so the model passes them correctly too.
   Files: `ai-insights/application/tools/metric.whitelist.ts` (+ spec), `tool-registry.ts`.

2. **Responses showed raw Markdown (`**0**`).** Both web (`chat-client.tsx`) and mobile render
   the answer as plain text, so the model's Markdown leaked through literally. **Fix:** added a
   plain-text instruction to the system prompt (server-side → fixes both surfaces at once, no new
   frontend dependency).

Verified: API typecheck clean, 285/285 tests pass (2 new whitelist tests). Needs a live re-test
in the e2e session (real ANTHROPIC_API_KEY + data) to confirm the model now returns the right
count in prose.

## Production-readiness audit (Head-of-Engineering review)

Evidence-based pre-launch audit written up as a living checklist:
`docs/03-engineering/production-readiness.md`. Headline: foundation is solid (config validated at
boot, no hardcoded secrets, refresh-token revocation, subscription guard, 285 tests), but there is
a **P0 tenant-isolation cluster that should gate the public launch**:
1. `GET /gyms/:gymId/conversations/default` has no tenant check at all (no `@CurrentUser`).
2. Org-type tokens bypass `assertGymAccess`/`assertPermission` on gym routes; no gym-belongs-to-org
   validation anywhere (IDOR).
3. No test guards the boundary (~88 gym-scoped use cases rely on manual `assertGymAccess`).
Recommended fix: a `GymAccessGuard` bound to `:gymId` + one parametrized cross-tenant e2e test.
P1 hardening: open CORS (`*` on HTTP + WS), no `/auth` rate limit, no helmet, shallow health check
(200 while DB down). P2: Sentry, cursor pagination.

## Nutrition AI feature — findings (e2e testing) + plan (NOT yet built)

User feedback on the member AI Coach nutrition tab (`apps/mobile/src/app/(member)/ai.tsx`,
`NutritionTab`). Confirmed root causes:
- **Markdown `**bold**` leaks into the UI.** `meal-suggestion.use-case.ts` prompt ends with "Use
  clear formatting" and returns raw `text`; `SuggestionCard` renders it as plain `<Text>`. Same
  class as the insights markdown bug.
- **Result is lost on navigate-back.** Unlike workout plans (persisted via `MemberWorkoutPlan` +
  `getLatestWorkoutPlan`), the meal suggestion is stored only in component state and saved nowhere
  server-side. Needs a persistence table + get-latest endpoint to survive unmount.
- **No generation parameters.** `POST ai/meal-suggestion` takes only gymId/memberId — the guided
  flow (today-vs-single-meal, target calories, macros, meal count) needs a params DTO.
- **AI Coach is undiscoverable.** `ai.tsx` is `HIDDEN` from the member tab bar; not linked from
  dashboard/hub. Users won't find it without exploring.
Proposed: (1) quick wins — plain-text prompt + persist "today's plan" + rename Nutrition→Meal Plan;
(2) guided pre-generation flow; (3) surface AI Coach prominently.

## "Log a Meal" photo analysis switched to Claude vision (was Gemini)

The member food-photo analyser (`analyse-meal.use-case.ts` → `VisionProviderPort`) ran on Gemini
(`gemini-2.0-flash`). Switched it to the Claude (Anthropic) vision API per request.

- New `AnthropicVisionProvider` (`common/adapters/ai/anthropic-vision.provider.ts`) implementing
  `VisionProviderPort.analyseImage`. Uses the official `@anthropic-ai/sdk` (already a dep, 0.102).
  **Downloads the image and sends base64** (with a browser User-Agent), mirroring the old Gemini
  provider — chosen over passing the URL to Claude because Anthropic's server-side fetcher is
  blocked by some hosts (confirmed: a Wikimedia URL 400'd "Unable to download the file" when passed
  as a URL source, but works fine when we download it ourselves). Thinking left off (simple
  extraction; Opus 4.x runs without thinking when the field is omitted).
- `vision-provider.module.ts` now wires the Anthropic provider, reading `ANTHROPIC_API_KEY` (reused
  from AI Insights) + `ANTHROPIC_VISION_MODEL` (default `claude-opus-4-8`, overridable via env —
  added to the Joi schema). Gemini provider file kept for easy rollback.
- **Live-verified end to end:** minted a member JWT, POSTed a real food photo to
  `/ai/analyse-meal` → HTTP 200 with correct structured JSON (identified turkey, red snapper,
  vegetables + calories/macros). API typecheck clean, 285/285 tests pass (no vision specs to
