# Progress — 2026-07-17

## P0 tenant-isolation guard (launch blocker) — DONE

Closed the entire P0 cluster from `docs/03-engineering/production-readiness.md` (findings 1–3) with
one structural fix: a global `GymAccessGuard`.

- **`apps/api/src/common/guards/gym-access.guard.ts`** — global guard, registered in `app.module.ts`
  as an `APP_GUARD` **before** `SubscriptionStatusGuard` (tenant check wins over subscription, so a
  foreign gym can't learn another org's billing state). Activates on any route with a `:gymId` param
  (all 77 gym-scoped routes use `@Param('gymId')` under a `gyms/:gymId` base — uniform). Decodes the
  JWT itself (mirrors the subscription guard), so no per-controller wiring:
  - `gym` token → `token.gymId` must equal the URL `:gymId`.
  - `org` token → the `:gymId` must belong to `token.organizationId` (gym→org lookup cached 300s).
  - `system_admin` → allowed; missing/invalid token or no `:gymId` → pass through (JwtAuthGuard 401s);
    unknown token shape → denied.
- Retained per-use-case `assertGymAccess` as defense-in-depth.
- **Test:** `gym-access.guard.spec.ts`, 10 cases (full decision matrix). API suite now 295/295,
  typecheck clean.
- **Live-verified** against the running API with two real gyms/orgs: own-gym → 200, cross-tenant gym
  token → 403 (closes the conversations-default leak), org-token cross-org → 403 (closes the
  org-bypass IDOR), org-token on its own gym → 200.

**This was the launch gate.** With it closed, remaining pre-launch work is the P1 hardening batch
(open CORS, no `/auth` rate limit, no helmet, shallow health check) and executing the infra runbook
(server provisioning, DNS/Caddy, backups + restore drill, CI/CD) — plus starting Apple Developer
enrollment (the long pole). Payments stay manual by design (owner decision; admin-verified flow
already built).

## Request-correlation logging (debuggability) — DONE

Closed the "can't trace a user-reported issue" gap. Doc: `docs/03-engineering/logging-and-observability.md`.

- **Correlation id:** `requestIdMiddleware` (first middleware in `main.ts`) mints/accepts an
  `X-Request-Id` and opens an `AsyncLocalStorage` scope (`common/context/request-context.ts`) for the
  whole request. Returned on the response header and in every error body (`requestId`).
- **Auto-tagged logs:** `RequestContextLogger` (`common/logger/`, wired via `app.useLogger` +
  `bufferLogs`) prefixes every log line with `[req:<id>]` — so all existing `Logger` calls become
  correlatable with no per-call change.
- **Failure logging with context:** `GlobalExceptionFilter` now logs **every** 4xx (warn) and 5xx
  (error + stack) with `user=<sub> type=<...> gym=<id> org=<id>` (previously only 5xx, no context,
  and the interceptor logged success only — 4xx were silent).
- **Verified live:** success carries `X-Request-Id`; a 404 error body includes a matching
  `requestId`; an inbound `X-Request-Id` is honored (trace spans the proxy). Typecheck clean,
  295/295 tests pass.
- **Follow-ups (documented):** surface the id on frontend error UI (web + mobile), then structured
  JSON via `nestjs-pino`, then Sentry (P2). Kept on the existing NestJS logger for now — pino is a
  clean drop-in later since the correlation model carries over.
