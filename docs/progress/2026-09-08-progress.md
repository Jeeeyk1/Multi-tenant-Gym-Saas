# Progress — 2026-09-08

## Dev port scheme migrated to the 9000 range — DONE

Moved every application off the `3000`-range dev ports onto a `9000` range, keeping the existing
tens-spacing convention so the mental mapping carries over unchanged.

| App | Old | New |
|---|---|---|
| API (`@gym-saas/api`) | 3000 (code fallbacks said 3001) | **9000** |
| Web (`@gym-saas/web`) | 3010 | **9010** |
| Admin (`@gym-saas/admin`) | 3020 | **9020** |
| Landing (`@gym-saas/landing`) | 3030 | **9030** |
| Mobile / Expo (`@gym-saas/mobile`) | 3099 | **9099** |

Postgres (5432) and Redis (6379) were left alone — infrastructure, not application ports.

### Two pre-existing inconsistencies fixed along the way

1. **API port fallbacks were stale.** The API has run on `3000` (root `.env`) for months, but every
   in-code fallback still said `3001` — `app.config.ts`, `main.ts`, the Joi `PORT` default,
   `apps/web/src/lib/api.ts`, `apps/mobile/src/services/api.ts`, `eas.json`, and both READMEs. Any
   environment that didn't set `PORT`/`*_API_URL` explicitly would have pointed at a dead port. All
   fallbacks now agree on `9000`.
2. **`CORS_ORIGINS` was never set anywhere**, so the API fell back to
   `http://localhost:3000,http://localhost:3002,http://localhost:3003` — which did *not* include the
   web app's real origin (3010) or admin's (3020). Browser-side calls and the Socket.IO chat upgrade
   were relying on that default being wrong-but-unused. Now set explicitly in `.env` and
   `.env.example` to `9010,9020,9030`, and the in-code default matches.
