## Sequential local port scheme (9001–9007) + one-command local setup — DONE

Supersedes the tens-spaced scheme from `2026-09-08-progress.md` (9000/9010/9020/9030/9099), which
was never committed.

| Service | Before | Now |
|---|---|---|
| API | 9000 (root `.env` had drifted to 9001) | **9001** |
| Web | 9010 | **9002** |
| Admin | 9020 | **9003** |
| Landing | 9030 | **9004** |
| Expo / Metro | 9099 | **9005** |
| Postgres (Docker host port) | 5432 | **9006** |
| Redis (Docker host port) | 6379 | **9007** |

### Decisions
- **9000 is skipped.** On the dev machine the Zscaler tunnel listens on `127.0.0.1:9000` as root, so
  the API dies with `EADDRINUSE`. It is invisible to a non-root `lsof`, which is why the root `.env`
  had quietly been moved to `PORT=9001` while every client still pointed at 9000 (web/admin/landing
  could not reach the API). The sequence therefore starts at 9001.
- **Postgres and Redis moved too.** 5432/6379 are the ports most likely to collide with other
  projects' containers. Only the Docker *host* mapping changed; the named volumes and data are
  untouched. Production docs still use 5432/6379.
- `.env.example` was not bootable: `API_PREFIX=api` while clients hardcode `/api/v1`, and the
  required `JWT_SECRET`, `JWT_REFRESH_SECRET`, `RESEND_API_KEY` were missing. Fixed.

### Files
- **New:** `scripts/setup-local.sh` — prerequisite checks, env file creation (never overwrites;
  generates JWT secrets on first run), port check (lsof + TCP connect, so root-owned listeners are
  caught), `docker compose up --wait`, Prisma generate, migrations; flags `--seed`, `--start`,
  `--start-all`, `--skip-install`.
- **Ports:** `docker-compose.yml`, `.env.example`, `apps/{api,web,mobile}/.env.example`,
  `apps/{web,admin,landing}/package.json`, `apps/mobile/package.json`, `apps/mobile/eas.json`,
  API config defaults (`app.config.ts`, `app.module.ts`, `main.ts`, `email.service.ts`), every
  `localhost:90xx` fallback in web/admin/landing/mobile, admin `new-gym-form.tsx` port hop,
  READMEs, `docs/04-api`, `docs/api` Postman collection, `docs/implementation`, `docs/deployment`
  (also fixed the `PORT` row that contradicted the nginx `proxy_pass`).
- **Local only (gitignored):** root `.env`, `apps/*/.env.local`, `apps/mobile/.env`.

## Access hardening (review Phase 0) — DONE

First batch from the full review (security, tenant isolation, scalability, maintainability).

- **Organization creation** (`POST /organizations`) is now system-admin only. No client called it;
  provisioning goes through the admin console.
- **Gym routes are covered by the global tenant guard.** `detail`, `profile`, `profile/logo` and
  `schedules` used `:id`, which `GymAccessGuard` (keyed on `:gymId`) did not see. Param renamed;
  URLs are unchanged for clients.
- **New `MemberAccessGuard`** (`common/guards/member-access.guard.ts`) on the member-scoped AI and
  food-log routes: the member must belong to the gym in the URL, and a gym-token caller must be that
  member or staff with `members.view` (GET) / `members.edit` (writes).
- **Landing chat** is rate-limited per IP (10/min, 100/day) and its DTO has length and array caps.
- **Auto-checkout and auto-suspend crons** page by id cursor. Previously a full batch of rows that
  did not qualify yet was re-read forever.
- **Seeds:** `apply-seeds.ts` skips `*dev_fixtures*` when `NODE_ENV=production`; deploy guide corrected.

### Decisions
- A guard rather than per-use-case checks for member routes: one enforced place, reusable for the
  other `/gyms/:gymId/members/:memberId/*` routes in the next phase.
- Cron fix kept minimal (cursor) rather than moving the threshold into SQL, so the existing specs
  and per-gym config logic stay as they are.

## Authorization fixes (review Phase 1, first batch) — DONE

Targeted fixes for routes where a secondary id from the URL or body was used without checking it
against the caller's gym or identity.

- **Chat delete:** the conversation must belong to the gym in the URL (`CONVERSATION_NOT_FOUND`).
- **Chat send:** `replyToId` must be a message in the same conversation (`REPLY_TARGET_NOT_FOUND`).
- **Weight log:** "self" now means the caller owns the member record; otherwise `members.edit` is required.
- **Token refresh:** a user who is not active staff must still be a member of the gym, matching login.
- **Leaderboard staff submission:** the target member must be in this gym.
- **Staff management:** new `modules/staff/domain/staff-management.rules.ts`. A gym-level caller cannot
  change their own roles or deactivate themself, and only a gym owner can grant or remove the owner
  role or act on an owner. Org-level callers are unrestricted. Added a `StaffRole` enum.

### Decisions
- The staff rule is a policy choice (owner-only control of the owner role) rather than a
  permission-subset check: it needs no extra queries and is easy to reason about.
- Explicit refresh-token revocation on deactivation was not added: with the refresh check, access
  ends when the current access token expires (15 minutes).

### Verification
- API typecheck and lint clean; **340 tests / 69 suites pass** (15 new tests).
- Live smoke test: member and staff login + refresh still work; a reused refresh token is rejected.
