# Progress — 2026-11-25

## Badges v2 — API (PR into develop)

**Decisions (agreed with the user):**
- Three categories, one equipped badge per category (three in total).
- Bronze, silver and gold lift ladders on the gym's leaderboard lifts:
  - weights are editable per gym, with our defaults (e.g. dumbbell bench 30/40/50 kg);
  - the actual weight lifted counts, not the estimated 1RM;
  - no separate men's and women's weights yet.
- Loyalty counts *active* membership months.
- Progress and rarity are shown.
- The "new badge" celebration is included.
- Badges come before the roles work.

### Built
- **Migration `0048_badges_v2.sql`:**
  - `category` on catalog, custom and member badges (backfilled), with a partial unique index for one equipped badge per category;
  - `tier` on milestone badges, with a unique (gym, lift, tier) index for active rungs;
  - duplicate catalog and milestone awards removed, then blocked by unique indexes;
  - `seen_at` (existing badges marked seen);
  - five loyalty catalog badges (1, 3, 6, 12 and 24 months);
  - the milestone creator column now allows empty values, for system-created ladders.
- **Domain:**
  - `badge-stats.ts`: streak, early bird / night owl and weekly habit now use the **gym's timezone** (they used UTC);
    active membership days come from the join date and renewals, skipping lapses and future prepaid days;
    progress and earned rules.
  - `lift-ladder.ts`: default weights per global lift, with category fallbacks.
- **Awards:**
  - idempotent (`createMany … skipDuplicates`);
  - a push notification on new badges (the Expo SDK is loaded lazily so Jest can import the modules);
  - cycle winners are notified too.
- **New endpoints:** collection, mark seen, list and save ladders. The equipped endpoint returns up to three badges
  and keeps the old `badge` field.
- **Ladders:**
  - default ladders are created when a lift joins the leaderboard;
  - saving a ladder credits lifts already approved;
  - switching a ladder off keeps members' earned rungs and stops it being recreated.
- **The daily cycle job** also unequips expired badges.
- **Security fixes** (open review items): awarding a custom badge checks it belongs to the gym; creating a
  milestone checks the lift is global or the gym's own.

### Review fixes (before commit)
- **Ladder setup when staff save leaderboard settings:** it was fire-and-forget with no error handling (an unhandled
  rejection could crash the API). It now waits for the step, logs failures, and the cycle setup does the same.
- **Membership months:** a month is now 30 active days and expiry dates count as active days. A 30-day plan reaches
  "1 month" and a 365-day plan "12 months" (they fell just short before).
- **Migration:** extra equipped badges in the same category are cleared before the unique index is created. Cycle
  wins are excluded by `source <> 'AUTO_CYCLE'` rather than `cycle_id IS NULL`, which becomes NULL when a cycle is deleted.
- **Concurrency:** equipping takes a per-member, per-category advisory lock, and saving a ladder a per-lift lock, so a
  double tap no longer hits the unique index and returns 500.
- **Switching a ladder back on** reuses its old rungs, so badges aren't credited twice. The collection still shows
  earned badges whose ladder or custom badge was switched off.
- **The collection** no longer loads stats twice or waits on push. It awards from the stats it already loaded, only
  when members view their own collection, and checks for missing ladders at most every 5 minutes per gym.
- **Push notifications** are fire-and-forget everywhere. The cycle job notifies winners after the next cycle is created.
- **The legacy `badge.rank`** carries only the leaderboard cycle rank, not ladder tiers.
- **Enums** replace the raw `'APPROVED'` and `'ACTIVE'` strings in the new queries.
- **Known limitation:** app versions from before Badges v2 show the first category's badge in the legacy `badge` field.
  This is acceptable because no such builds have been released.

## Badges v2 — quality pass (PR into develop)
New standing rule from the owner: every change is reviewed before commit for being **maintainable, scalable,
easy to debug, and logging important information**. Two reviewers went over all of Badges v2 (API and clients),
and their "fix now" items are in this PR.

### API
- **Success logs** for every award path, with gym, member and badge keys or ids:
  - auto (`source=AUTO_SYSTEM keys=[…]`);
  - milestone (`exercise=… kg=… milestones=[id:tier]`);
  - staff award (`custom=… by=…`);
  - cycle close (`awards=… members=[id:rank]`).
- **Push:** Expo tickets are checked and rejected ones logged at `warn`, with no tokens. A `debug` line records
  devices and rejected counts. Errors carry gym, exercise and weight context and pass the stack.
- **Cycle cron:** each gym is caught on its own. One failing gym no longer stops the others or the expired-badge
  unequip, and the summary line reports closed, failed and total.
- **Close cycle:** winners are worked out first. Then closing the cycle, the awards and opening the next cycle
  happen in one transaction (`completeCycle`), so a failure leaves the cycle active for a clean retry: no
  partial awards, and no gym left without a cycle. Notifications go out only after success.
- **Ladders:** save, disable and default-creation are logged with who did it, the weights and how many past lifts
  were credited. Only leaderboard lifts can get a ladder (`NOT_A_LEADERBOARD_LIFT`).
- **Check-in cost:** auto checks skip badges the member already holds. When nothing is left to earn, the seven
  activity-stats queries are skipped entirely, which covers most check-ins for long-time members.
- **Collection:** a failed award pass is logged at `warn` and no longer fails the whole page.
- Raw `'ACTIVE'`, `'COMPLETED'` and `'APPROVED'` strings are replaced with enums.
- **New tests:** close-cycle (transaction contents, no notification on failure), cron resilience (one gym fails,
  the next still closes), check-auto skipping stats, and the ladder leaderboard-lift rule. 463 tests pass.

### Web
- **`getOr(endpoint, fallback)`** in `lib/api.ts` replaces silent `.catch(() => [])` on the badges, chat and
  leaderboard pages. Failures are logged with the request ref. The leaderboard and custom badges show
  "Could not load" instead of looking empty.
- Badge actions use `formatApiError`, so users see a Ref id they can quote.

### Mobile
- The badge hooks moved from `hooks/members.ts` to `hooks/badges.ts` with one key factory (`badgesKeys.mine`,
  `equipped`, `collections`). This removes the hand-typed query key and the import cycle.
- The collection refreshes the member's badges from its query function instead of an effect, so remounting
  the screen no longer triggers extra fetches.

### Docs
- `logging-and-observability.md` documents the event log style and `getOr`.

### Review fixes (before commit)
- **Push tokens:** Expo's most common rejection message (`DeviceNotRegistered`) quotes the device token. It is
  now masked as `[token]` before logging.
- **Double close:** `completeCycle` only closes a cycle that is still active, inside an interactive transaction.
  A second run on the same cycle (e.g. a lock expiring during a long run) changes nothing and logs a warning,
  instead of awarding twice and opening a second cycle.
- The collection warning includes the stack, and `getOr`'s fallback type defaults to the data type.
- **Tests added:**
  - an award race doesn't notify;
  - switching a ladder off skips the leaderboard-lift check;
  - the cron still unequips when loading cycles fails;
  - an already-closed cycle is skipped.

  466 tests pass.

### Deferred (backlog)

- Shared gym-access and permission assertions.
- A short cache for `/badges/equipped`, and a filter by user ids for large gyms.
- One `BADGE_ICONS` list validated in the API.
- Memoise chat rows.
- Mobile badge enums are kept as a local mirror: switching to `@gym-saas/contracts` needs a Metro check on a

- **Local web typecheck:** with this machine's install, an uncached `tsc` reports React 18 type errors in files
