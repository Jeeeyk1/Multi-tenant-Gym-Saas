# Progress — 2026-11-25

## Badges v2 — API (PR into develop)

**Decisions (agreed with the user):**
- Three categories, one equipped badge per category (three in total).
- Bronze, silver and gold lift ladders on the gym's leaderboard lifts:
  - weights are editable per gym, with our defaults (e.g. dumbbell bench 30/40/50 kg);
  - the actual weight lifted counts, not the estimated 1RM;
  - no separate men's and women's weights yet.
- Loyalty counts *active* membership months.
- Progress and rarity are shown.
- The "new badge" celebration is included.
- Badges come before the roles work.

### Built
- **Migration `0048_badges_v2.sql`:**
  - `category` on catalog, custom and member badges (backfilled), with a partial unique index for one equipped badge per category;
  - `tier` on milestone badges, with a unique (gym, lift, tier) index for active rungs;
  - duplicate catalog and milestone awards removed, then blocked by unique indexes;
  - `seen_at` (existing badges marked seen);
  - five loyalty catalog badges (1, 3, 6, 12 and 24 months);
  - the milestone creator column now allows empty values, for system-created ladders.
- **Domain:**
  - `badge-stats.ts`: streak, early bird / night owl and weekly habit now use the **gym's timezone** (they used UTC);
    active membership days come from the join date and renewals, skipping lapses and future prepaid days;
    progress and earned rules.
  - `lift-ladder.ts`: default weights per global lift, with category fallbacks.
- **Awards:**
  - idempotent (`createMany … skipDuplicates`);
  - a push notification on new badges (the Expo SDK is loaded lazily so Jest can import the modules);
  - cycle winners are notified too.
- **New endpoints:** collection, mark seen, list and save ladders. The equipped endpoint returns up to three badges
  and keeps the old `badge` field.
- **Ladders:**
  - default ladders are created when a lift joins the leaderboard;
  - saving a ladder credits lifts already approved;
  - switching a ladder off keeps members' earned rungs and stops it being recreated.
- **The daily cycle job** also unequips expired badges.
- **Security fixes** (open review items): awarding a custom badge checks it belongs to the gym; creating a
  milestone checks the lift is global or the gym's own.

### Review fixes (before commit)
- **Ladder setup when staff save leaderboard settings:** it was fire-and-forget with no error handling (an unhandled
  rejection could crash the API). It now waits for the step, logs failures, and the cycle setup does the same.
- **Membership months:** a month is now 30 active days and expiry dates count as active days. A 30-day plan reaches
  "1 month" and a 365-day plan "12 months" (they fell just short before).
- **Migration:** extra equipped badges in the same category are cleared before the unique index is created. Cycle
  wins are excluded by `source <> 'AUTO_CYCLE'` rather than `cycle_id IS NULL`, which becomes NULL when a cycle is deleted.
- **Concurrency:** equipping takes a per-member, per-category advisory lock, and saving a ladder a per-lift lock, so a
  double tap no longer hits the unique index and returns 500.
- **Switching a ladder back on** reuses its old rungs, so badges aren't credited twice. The collection still shows
  earned badges whose ladder or custom badge was switched off.
- **The collection** no longer loads stats twice or waits on push. It awards from the stats it already loaded, only
  when members view their own collection, and checks for missing ladders at most every 5 minutes per gym.
- **Push notifications** are fire-and-forget everywhere. The cycle job notifies winners after the next cycle is created.
- **The legacy `badge.rank`** carries only the leaderboard cycle rank, not ladder tiers.
- **Enums** replace the raw `'APPROVED'` and `'ACTIVE'` strings in the new queries.
- **Known limitation:** app versions from before Badges v2 show the first category's badge in the legacy `badge` field.
  This is acceptable because no such builds have been released.

## Badges v2 — mobile (PR into develop, stacked on the API PR)

### Built
- **`BadgeMedal`** draws each badge as a gym plate. The shape gives the category: a round plate for Consistency, a
  shield for Loyalty and a hex for Strength. The rim gives the tier: gold, silver, bronze, or iron when there is no
  tier. Locked badges are grey with a lock. Icons are Ionicons; an unknown name falls back to `ribbon`.
- **`BadgeStack`** shows up to three small medals next to names in community chat, leaderboard rows and Who's Here.
  Tapping it opens **`EquippedBadgesSheet`**, which shows each badge's name, category and description. Phones have
  no hover, so details are a tap away.
- **Profile:** three equipped slots, one per category, linking to the collection. The header shows the stack.
- **Collection screen** (`(member)/badges`, a hidden tab route):
  - the equipped slots, then a grid per category;
  - locked badges show a progress bar;
  - tapping a badge opens **`BadgeDetailSheet`**: progress, earned date, rarity, times earned, and Equip/Unequip.
- **`NewBadgeCelebration`** on the dashboard:
  - shows the newest unseen badge with a stamp animation (skipped when the OS asks for reduced motion), and
    announces it to screen readers;
  - Equip says when it will replace the badge already in that category;
  - Equip or Later marks every unseen badge as seen.
- **Staff badge list** now shows a medal. Before, it printed the icon name as text.
- `EquippedBadgeChip` and the old single-badge display type have been removed.

### Verification
- Mobile typecheck passes. Mobile lint reports no errors and no new warnings in the touched files.
- Not yet checked on a device: medal rendering, the stamp animation, and the sheets.

### Review fixes (before commit)
- The celebration opens only while the dashboard is on screen. Tabs stay mounted, so it could open over another
  screen's sheet (two iOS modals at once can get stuck).
- Loading the collection refreshes the member's badges, because it can award new ones. The profile and the
  celebration then pick them up.
- A failed Equip in the celebration shows an error and keeps the card open. Before, it closed and marked the badge seen.
- The detail card clears an old equip error when another badge is opened.
- Accessibility:
  - the profile slots read the equipped badge names;
  - the medal stack has a larger tap area;
  - collection cells say "equipped";
  - the sheet backdrop is a button.
- `BadgeCategory` / `BadgeTier` enums live in `constants/enums.ts`, and medal rim colours in `constants/theme.ts`.
- **Deferred:** `hooks/members.ts` still spells out the collection query key, to avoid an import cycle with
  `hooks/badges.ts`. A shared query-keys module would remove that, as a later clean-up.
