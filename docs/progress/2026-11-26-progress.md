## Phase 4B — roles, step 1: shared authorization (branch `refactor/shared-authz`)

Roles plan agreed with the owner today (decisions in memory `project-roles-4b`):
- Owner, Staff and Trainer. Staff can manage the leaderboard by default, and the owner can switch that off per
  gym.
- Trainers see members' name and status only.
- A member view for people who are also members.
- AI assistant: Owner only for now.
- Gyms are set up very differently (a solo owner, staff who coach, rarely a full team), so roles combine and the
  owner adjusts them per gym.

### Done (no behaviour change)
- `common/auth/authorization.ts`: `assertGymAccess`, `assertPermission`, `assertAnyPermission`, `hasPermission`.
  The new `Permission` enum covers every key in the `permissions` table.
- Replaced 41 copies of `assertGymAccess`, 32 of `assertPermission`, 4 of `assertStaffManage` and 1 of
  `assertStaffView`, plus 18 inline `caller.permissions.includes('…')` checks and 19 inline gym-access checks,
  across about 70 files. Error codes and messages are unchanged.
- The pre-commit review confirmed there is no behaviour change for gym or org tokens. Every inline check was
  already narrowed to gym tokens.
  - **One edge:** a platform-admin token passes `GymAccessGuard`. Listing announcements used to crash (500) for
    it and now returns the staff list. That matches how `assertPermission` already treated admin tokens.
  - **Kept as is:** `mark-badges-seen` deliberately rejects org tokens. `assertCanManageStaff` is a domain rule.
- Tests for the helpers, and `auth-and-rbac.md` documents the convention.

### Next
- Step 2: migration `0051`:
  - roles become OWNER, STAFF and TRAINER;
  - a `members.details` permission (contact and payment info) that Trainers don't get;
  - per-gym owner switches on what Staff can do;
  - the role is chosen at invite time.
- Then the web and mobile changes.

## Phase 4B — roles, step 2a: Owner / Staff / Trainer (branch `feat/roles-owner-staff-trainer`, stacked on `refactor/shared-authz`)

### Done (API, DB, docs)
- **Migration `0051_roles_owner_staff_trainer`:**
  - GYM_OWNER → OWNER and MANAGER → STAFF. FRONT_DESK holders move to STAFF, and the old roles are removed.
  - New permission `members.details`.
  - Role permissions are rebuilt for the three roles.
  - Checked on the local data (dry run, rolled back) and on a throwaway fresh DB (all migrations and seeds, roles
    and dev accounts right, no schema drift).
  - Seeds `001`/`002`/`003` match for fresh databases.
- **Matrix:**
  - OWNER: everything.
  - STAFF: members incl. details and member operations, check-ins, announcements, chat moderation, plans, the
    full leaderboard including `leaderboard.manage`, and badge awarding.
  - TRAINER: `members.view`, check-ins, chat moderation, PR submit and review, badge awarding.
- **Trainers see name and status only.** `visibleMember()` reduces member list and detail responses without
  `members.details`.
  - Plans now need `plans.view`.
  - Renewals, the member fitness profile, staff access to a member's QR, weight logs and `MemberAccessGuard`
    reads (AI member routes) now need `members.details`.
- **Lift ladders** (`GET/PUT badges/ladders`) now need `leaderboard.manage` instead of `badges.manage`, so Staff can
  manage them (and the owner switch in step 2b covers them). Custom badges stay Owner-only.
- **Staff who are also members:** `gymClaims()` (`identity/domain`) builds the token for login and refresh. Staff who
  also have a membership get `MEMBER` and the member permissions too, which enables the member view in the app.
- **Invite with role:** `POST /staff` takes an optional `role`, assigned in the same transaction. Only an owner can
  invite an owner. Invites and role assigns and removes are logged with `by=`.
- **Contracts:** `StaffRole` is OWNER, STAFF, TRAINER.
- **Dev accounts:** `manager@devgym.com` is now OWNER, so every screen works locally. New `staff@devgym.com`
  (STAFF) and `trainer@devgym.com` (TRAINER), all with `Password123!`.
- **Docs:** `staff-and-rbac.md` is rewritten (it was half broken). `auth-and-rbac.md`, the API reference, the schema
  reference, billing, first-time setup and the Postman collection use the new roles.
- **Tests:** `gymClaims`, `visibleMember`, `assertCanGrantRole`, and the updated specs.

### Review fixes (before commit)
- **Mobile trainer crash:** manual check-in and member search called `.toLowerCase()` on `membershipNumber` and `email`,
  which trainers no longer receive. The searches now skip missing fields. The rest of the trainer screens come in
  the mobile PR.
- **Membership numbers:** active check-ins, check-in history and pending PRs still returned them to trainers.
  `withoutMemberDetails()` (`common/auth/member-details.ts`) removes them without `members.details`.
- **Web:** the Badges page (lift ladders) is in the menu for `leaderboard.manage`, so Staff can reach it. The
  "New Badge" button shows only with `badges.manage`. The staff list colours use OWNER, STAFF and TRAINER.
- Migration header and seed 003 comments corrected.
- **Tests:** invite with role (same call, Owner-only for OWNER), login for staff who are also members, and
  `withoutMemberDetails`. 490 tests pass.
- **Known:** tokens issued before deploy keep the old role names until they refresh (at most the access-token
  lifetime). No release yet, so this is acceptable.
- Some older specs still use `roles: ['MANAGER']` fixtures; the name has no effect on what they test.
