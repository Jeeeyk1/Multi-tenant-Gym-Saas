# Progress — 2026-11-26

## FitOps visual refresh — review fixes (branch `feat/fitops-visual-refresh`)

Continues `2026-11-25-progress.md`. Fixes from a code review of the branch against `main`.

- **`onAccent()` handles every hex form the API accepts** (`@IsHexColor()`: `#RGB`, `#RGBA`, `#RRGGBB`,
  `#RRGGBBAA`, with or without `#`). Before, anything but 6-digit hex fell back to white text, e.g. white on
  `#FF0`. Same file in `apps/mobile/src/theme/accent.ts` and `apps/web/src/lib/accent.ts`; helpers other
  than `onAccent` made module-private.
- **End Workout button** (`(member)/workout.tsx`): border color restored to the error color (it had a black
  1.5 px outline on iOS).
- **Gym login page / code entry:** stale comment fixed; the unused `primary`/`secondary` color query params are
  no longer added in `lib/auth.ts` or read on `[code]/login`. Branding fetch now runs when name and logo are
  both missing.
- **Dialog backdrops:** new `--scrim` token (Navy in light, black in dark) used as `bg-scrim/60`; the previous
  `bg-surface-inverse/60` lightened the page in dark mode.
- **Docs:** `docs/implementation/web-admin-dashboard.md` theming section rewritten for the FitOps tokens (gym
  colors no longer applied to the staff app).
- Review item about the branding preview flickering on partial hex input was not reproducible: the preview
  color only updates on a complete 6-digit value. No change.

### Open decision

### Known, pre-existing
- Mobile builds translucent tints by appending hex alpha (`theme.primary + '20'`); that produces an invalid
  color if a gym's saved color is a 3-digit hex.

### Verification
- Web typecheck clean, lint 1 pre-existing `<img>` warning; mobile typecheck clean, lint 15 pre-existing
  warnings. `onAccent()` checked against 3/4/6/8-digit and invalid inputs.
