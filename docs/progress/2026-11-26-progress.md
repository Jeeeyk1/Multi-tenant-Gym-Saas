## FitOps visual refresh — review fixes (branch `feat/fitops-visual-refresh`)

Continues `2026-11-25-progress.md`. Fixes from a code review of the branch against `main`.

- **`onAccent()` handles every hex form the API accepts** (`@IsHexColor()`: `#RGB`, `#RGBA`, `#RRGGBB`,
  `#RRGGBBAA`, with or without `#`). Before, anything but 6-digit hex fell back to white text, e.g. white on
  `#FF0`. Same file in `apps/mobile/src/theme/accent.ts` and `apps/web/src/lib/accent.ts`; helpers other
  than `onAccent` made module-private.
- **End Workout button** (`(member)/workout.tsx`): border color restored to the error color (it had a black
  1.5 px outline on iOS).
- **Gym login page / code entry:** stale comment fixed; the unused `primary`/`secondary` color query params are
  no longer added in `lib/auth.ts` or read on `[code]/login`. Branding fetch now runs when name and logo are
  both missing.
- **Dialog backdrops:** new `--scrim` token (Navy in light, black in dark) used as `bg-scrim/60`; the previous
  `bg-surface-inverse/60` lightened the page in dark mode.
- **Docs:** `docs/implementation/web-admin-dashboard.md` theming section rewritten for the FitOps tokens (gym
  colors no longer applied to the staff app).
- Review item about the branding preview flickering on partial hex input was not reproducible: the preview
  color only updates on a complete 6-digit value. No change.

### Open decision

  pre-selects Mint and saves it. Waiting on the user.

### Known, pre-existing
- Mobile builds translucent tints by appending hex alpha (`theme.primary + '20'`); that produces an invalid
  color if a gym's saved color is a 3-digit hex.

### Verification
- Web typecheck clean, lint 1 pre-existing `<img>` warning; mobile typecheck clean, lint 15 pre-existing
  warnings. `onAccent()` checked against 3/4/6/8-digit and invalid inputs.

## FitOps app branding (branch `feat/fitops-app-brand`)

### Done
- **Mobile name:** FitZone → **FitOps** (`app.json` name and the HealthKit permission text). The bundle id, slug
  and scheme are unchanged: they're store and EAS identifiers, decided in 4D.
- **App icon:** `icon.png` is regenerated from `design/landing/logo/fitops-app-icon-member.svg` (Volt dot on
  Navy, opaque 1024). The new `adaptive-icon.png` (Android foreground, mark inside the safe zone) and
  `splash-icon.png` (native splash) sit on Navy `#0A2540`.
- **Launch hand-off:** the native splash, the font-loading screen and the animated `AppSplash` are all Navy, so
  there's no colour flash. Until the gym is known, `AppSplash` shows the FitOps wordmark ("Fit" Manrope 800 +
  "Ops" Manrope 500). After that it shows the gym's name, since members see their gym and not FitOps.
- **Loader:** `AppLoader` builds the FitOps mark tile by tile, then the dot lands, in a loop. It uses the native
  driver and holds a static mark when reduce motion is on. The dot is the gym's accent in the member app and
  FitOps blue in the staff app. The startup auth check now uses it too.
- **`Logo`** takes `accent` and `tile`. Tiles are white on dark and Navy on light. A new `Wordmark` component, and
  `BRAND` constants in `constants/theme.ts`.
- **Web and admin:** titles changed from LiftHub to FitOps, and both get the FitOps favicon (`app/icon.svg`, same as
  the landing page).

### Review fixes (before commit)
- **iOS native project:** `apps/mobile/ios/` is committed, so iOS builds read it instead of `app.json`. These are now
  synced by hand:
  - display name FitOps and the HealthKit strings (`Info.plist`);
  - the new 1024 icon (`AppIcon.appiconset`);
  - the splash background, Navy `SplashScreenBackground` used by `SplashScreen.storyboard` in place of
    `systemBackgroundColor`.

- **Follow-up (owner decision):** `ios/` was then regenerated with `npx expo prebuild -p ios --clean` and is
  still committed.
  - The target, scheme and workspace are now `FitOps`. Open `FitOps.xcworkspace` in Xcode from now on.
  - HealthKit entitlements, `AppDelegate`, every `Info.plist` key and the bundle id `com.gymSaas.mobile` match the
    old project.
  - The splash is now Expo's generated imageset on Navy.
  - `Podfile.lock` picks up `NitroModules`, which a dependency added since the old lock was made.
  - Going forward, change native config in `app.json` and re-run prebuild instead of editing `ios/` by hand.
- **Wordmark:** it rendered at 15px because the app's `Text` adds the body size to nested spans. It now uses RN
  `Text` with an explicit line height.
- **Mark colours follow the surface:** `Logo` tiles are always white (it only sits on dark surfaces). `AppLoader` is
  always white or blue on staff screens. On member screens in light mode it is Navy, and Volt falls back to Navy
  there (Volt is never drawn on light).
- The Android adaptive foreground and splash mark are scaled to 44%, so the rounded tiles stay inside the safe circle.

### Not changed
- The `lifthub.app` default for `APP_HOST` (web middleware) and `docs/03-engineering/subdomain-routing.md`. The
  production domain will be `fitops.app` or `fitops.com`, not final yet.
