## FitOps design system, step 1: shared kit foundation (branch `design/ui-kit-foundation`)

### Completed
- **`packages/ui` is now the FitOps design system for staff web and admin.** It ships TypeScript source (Next
  transpiles it via `transpilePackages`), so there is no build step and edits hot-reload in the apps.
- **Tokens** (`packages/ui/src/styles/tokens.css`):
  - the light and dark colour variables, moved from `apps/web/src/app/globals.css` unchanged;
  - the three springs from mobile (`snappy`, `gentle`, `bouncy`) as CSS `linear()` easing, with a cubic-bezier
    fallback;
  - shared keyframes and the reduced-motion rule.
- **Tailwind preset** (`packages/ui/tailwind-preset.js`): web's colour, type, radius and size scale, plus
  `ease-snappy/gentle/bouncy`, matching durations and `animate-pop-in / toast-in / shimmer / spin-fast`. Web's
  `tailwind.config.ts` is now the preset plus content paths.
- **Components:**
  - `Button`: idle, loading and success states; `buttonClasses()` for links.
  - `Icon`: Ionicons, the same set as mobile, drawn as a mask so it takes the text colour.
  - `TextField`, `SelectField`, `TextAreaField`: label, hint and error wired with `aria-describedby`.
  - `Dialog`: native `<dialog>`, so focus trap, Esc and focus return come from the browser.
  - `ConfirmProvider`/`useConfirm` and `ToastProvider`/`useToast`: same API as web's old versions; toasts now
    have `aria-live` and an optional Undo action.
  - `Skeleton`, `EmptyState` (with an error tone), `StatusPill`, `SegmentedControl` (gliding indicator), `Spinner`.
- **Web:** depends on `@gym-saas/ui` and imports the tokens in the root layout. `components/ui/confirm-dialog.tsx`
  and `toast-provider.tsx` now re-export the kit, so existing imports work. This also fixes the old confirm
  dialog's animation, which used classes from a Tailwind plugin that was never installed.

### Decisions
- The preset is plain JS so Tailwind loads it without a TypeScript step.
- No icon library added: web already uses `ionicons/icons` (badges), and it matches mobile.
- Admin moves onto the kit in step 4. Its own colour variables would clash with the shared ones if mixed now.

### Verification
- Kit and web `tsc --noEmit` pass; web lint is clean. The web login page renders as before (checked with a
  screenshot). The live dev servers (API 9001, web 9002, admin 9003, Metro 9005) run from this worktree.

## FitOps design system, step 4b: admin tables (branch `design/admin-tables`)

PR #40 (step 4a) was merged first, after its CI run passed.

### Completed
- **API (read-only, admin module):**
  - `GET /admin/gyms` takes `search` (name, code or city, case-insensitive) and `status` (new `GymStatus` enum in
    `common/enums`).
  - `GET /admin/users` takes `search` (name or email) next to the existing `gymId`.
  - Both validate through `ListGymsQueryDto` / `ListUsersQueryDto`: `limit` at most 100, and a blank search means no
    filter.
  - New specs for both use cases.
- **Kit:**
  - `Pagination`: "21–40 of 45 gyms", Previous/Next, and windowed page numbers. It renders links, so pages are
    shareable; pass `linkAs={Link}` for client navigation.
  - `PageHeader`: the same title block on every page.
  - `buttonClasses()` moved to `button-classes.ts` (no `'use client'`) so server pages can style a `<Link>` as a
    button. Calling it from the client-only Button file failed on the server.
- **Admin:**
  - `ListToolbar`: a debounced search box and a status `SegmentedControl`, with state in the URL. Changing a filter
    goes back to page 1.
  - **Gyms:** search, status filter, paging of 20, `StatusPill`, empty states for "no gyms" and "no matches",
    error state. It used to stop at the first 50 with no paging.
  - **Users:** search and paging. It also used to stop at 50.
  - **Invoices:** the kit `Pagination` instead of every page number, and an error state. A failed load used to look
    like "No invoices yet".

### Decisions
- These endpoints sit in the admin module, which the plan gives to the Security stream. The owner is running only
  the design stream, and the change is a read-only filter, so it was made here.

### Verification
- 623 API tests pass. API, admin, web and kit `tsc` pass. Admin lint shows only existing `any` warnings.
