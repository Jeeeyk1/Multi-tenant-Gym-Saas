## Phase 4B — roles, web (branch `feat/web-roles`)

### Done
- **`apps/web/src/lib/roles.ts`:** role labels, plain descriptions for the invite form, and `usesWebDashboard()`.
  The web dashboard is for Owner or Staff. Trainer-only and member-only accounts use the app, and someone who is
  Staff and also coaches keeps the dashboard.
- **Invite form:** a role choice with a description of each role (Staff preselected, Trainer, and Owner shown to
  owners only), sent with the invite (`role` on `POST /staff`). The `OWNER_ROLE_PROTECTED` error has its own message.
  Role chips and the assign dropdown use readable names, and only owners are offered Owner.
- **Settings → Team permissions:** one switch per role setting (`GET/PUT /role-settings`). It starts with "Staff can
  manage the leaderboard", updates optimistically and rolls back with a toast on error. The text explains that
  changes apply within 15 minutes.
- **Trainers on web:** sign-in and the dashboard layout send them to `/[code]/not-staff?as=trainer`, a "Trainers use
  the mobile app" page. Members keep the existing copy.
- **Page guards:** settings, staff, badges, plans, renewals, announcements, chat, check-ins and leaderboard config
  redirect to the dashboard without the same permission as their menu item. Before, typing a URL showed an empty
  page with failing actions (the API always refused, so no data leaked).
- **Staff actions** use `formatApiError`, so errors show a Ref id.

### Review fixes (before commit)
- **Members who reach `/dashboard` got the trainer copy.** The layout now sends members to `as=member` and trainers
  to `as=trainer`.
- **More page guards:** member list and detail (`members.view`), Add member (`members.create`), leaderboard
  (`leaderboard.view`), and pending PRs (`leaderboard.review`).
- **`updateRoleSetting`** takes the gym from the session (not the browser), checks the value is a boolean, and logs
  failures with the code and request ref.
- **Accessibility:** the switch has `aria-describedby` for its description, and the role cards show a focus ring.
- **Pre-existing, not fixed:** gym tokens carry no `gymCode`, so `user.gymCode` is always empty (the sidebar code too).
  If the gym details can't load, a trainer falls back to `/`. Adding `gymCode` to the token is a small API
  follow-up.
