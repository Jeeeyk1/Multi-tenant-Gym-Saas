## Security — infrastructure plan and API standards (docs only)

### Done
- **`docs/deployment/infrastructure-security.md` (new):** the target security setup for test and prod, layer by layer:
  - Cloudflare edge: Tunnel so the server has no inbound ports, WAF, auth rate-limit rule, Bot Fight Mode off for the API host.
  - Cloudflare Access in front of the admin app and the test web and admin apps.
  - SSH over Tailscale. Postgres and Redis publish no Docker ports, because Docker port mappings bypass `ufw`.
  - Least-privilege Postgres roles (`gym_app`, `gym_migrator`, `gym_backup`) and a Redis ACL user.
  - Secrets per environment, kept in GitHub Environments and a root-owned env file.
  - One scoped provider key per environment, with spend limits.
  - Encrypted off-box backups using a write-only R2 token, plus a monthly restore drill.
  - Monitoring and audit log, an incident runbook, and Data Privacy Act duties.
  - Rollout dated against the Dec 8 test-env and Jan 12 beta milestones.
- **`docs/03-engineering/api-security.md` (new):** rules for every API change:
  - token types and audiences, refresh rotation with reuse detection, MFA, one-time tokens sent by email only and stored hashed;
  - fail-closed guards, secondary ids looked up with `gymId`, a public routes table;
  - DTO limits including WebSocket handlers, one trusted client-IP helper, upload content checks, SSRF rule;
  - response mapping, and a new-endpoint checklist for PRs.
- **`docs/deployment/first-time-setup.md`:**
  - links to the security target;
  - the Nginx example now overwrites `X-Forwarded-For` instead of appending to it.

### Decisions
- The public docs state standards only. The list of current gaps found by the 2026-11-26 local scan stays in
  `docs/private/security-scan-2026-11-26.md` (not committed; the repo is public).
- The admin app gets Cloudflare Access in front of it, rather than being reachable publicly with only its own login.

## Phase 4C — AI cost controls, part 1: API (branch `feat/ai-cost-caps`)

Decisions (memory `project-ai-cost-caps`):
- Monthly caps by plan tier, with my proposed defaults: Starter $1.50 + $2.00, Standard $2.50 + $3.50, Pro $5.00 + $7.00.
- Daily limit: Owner 40, Staff 15.
- Staff get the assistant, without revenue questions.

### Done
- **Migration `0053_ai_cost_caps`:**
  - `ai_usage_log` gains `model`, input and output tokens, and `cost_usd_micros`, plus a (gym, feature, time) index.
  - `plans` gains the assistant and member AI caps per tier.
  - Staff get `insights.query`.
  - Seed `003` matches. Seed `004` repeats the per-tier caps, because it creates plans after the migrations on a fresh DB.
- **Every AI provider** reports input tokens, output tokens and model. `ai-pricing.ts` turns that into cost; unknown
  models are charged at the highest price.
- **`modules/ai-usage`** (`AiAllowanceService`): plan and period lookup, the two pools, the assistant's daily limit
  per person, and friendly 429s with reset dates. Failures are logged.
- **Staff assistant:**
  - Uses the allowance, replacing the old token quota, which also counted members' AI (that was the bug).
  - Ceilings: 6 history turns, 4 steps, 800 tokens.
  - Usage is recorded even when a step fails.
  - Revenue tools are refused without `reports.view`.
  - The web and mobile chats send only the last 6 turns, which fixes "chat breaks after ~10 messages".
- **Member AI:** checks the gym pool before the per-member limit, and records cost on completion.
- **Meal photos** default to Claude Haiku (was Opus).
- **`GET /insights/usage`** for the meter.
- **Docs:** `docs/02-domains/ai-usage.md`, the API reference and the roles matrix.
